# TODO011 제품 원장 기록 대조

원본: https://app.notion.com/p/3e82cda7782b8163ba07e8d4dd4e9a62

기존 `npm run audit:daily -- YYYY-MM-DD` 보고서에 회사별 제품 원장 표/JSON이 포함된다. 점검 대상일과 현재 stock의 수집일은 별도다. 컬렉션 전체 수집 성공은 내용 진실/실측 증명이 아니고, 여러 컬렉션 수집은 원자적 스냅샷이 아니다. 운영 실행은 읽기 권한과 환경 확인 뒤 담당자가 별도로 수행한다.

운영 읽기의 주문 중 items 배열이 없거나 품목 줄이 객체가 아니면 ID/회사/상태/필드 이름을 입력 진단으로 보존하고, 해당 주문을 정상 계산에 포함하지 않는다. 정상 주문 점검은 계속하지만 그 회사 제품 대조 전체는 입력미확인으로 표시한다. 이런 문서를 메타데이터/빈 주문으로 추정해 무시하지 않는다. 전체 컬렉션 읽기가 실패하면 보고서 생성도 중단한다.

오프라인 파일 대조(인증/DB 접근 없음):

```sh
npm run audit:daily -- --input 로컬전용/011-input.json --output 로컬전용/011-report.json
```

입력 예시(합성 자료):

```json
{
  "companyId": "taebaek", "snapshotDate": "2026-10-10", "complete": true,
  "items": [{"id":"sample","name":"병","spec":"300ml","unit":"개","type":"product","stock":12}],
  "orders": [], "receipts": [], "inventoryEntries": [], "returnOperations": [],
  "itemBoms": [], "itemPacks": [], "physicalEvidence": []
}
```

실제 입력은 기존 원문 전체 배열을 사용하고 날짜는 현재 재고를 읽은 KST 날짜로 지정한다. `complete:true`는 호출자의 수집 성공 확인값일 뿐 수집 증명은 아니다. 누락 배열/불완전 확인값/비정상 수량은 보고서를 만들기 전에 거절한다. 빈 배열을 넣어 실제 기록을 생략해도 이 도구가 완전성을 증명해 주지는 않는다. 기존 출력 파일과 입력 파일은 덮어쓰지 않는다.

실측 증빙은 `physicalEvidence`의 `{itemId,anchorId,targetQty,createdAt,evidenceRef}`이며 검토한 실물 조사표만 제공한다. 최신 앵커 원문과 정확히 일치해야 한다. `stocktake-` 이름이나 상태→로트 전산 보정만으로 증빙을 만들지 않는다. 기존 운영 읽기 경로에는 증빙 입력이 없으므로 앵커는 전산 기준으로만 표시한다.

- 전산기준만: 기존 계산 재고/현재 stock/gap/앵커 시각을 진단용으로 표시.
- 기준없음: 현재 stock을 역산하므로 독립 계산 재고를 표시하지 않음.
- 기록일치/불일치: 확인된 최신 실측 증빙 이후 저장 기록 대조.
- 입력미확인: 날짜/수량/전체 입력 확인 필요.
- 원료별도대조: 제품 원장으로 원료 네 축을 검증하지 않음. 기존 일일 원료 점검은 유지.

기존 `buildItemLedger`는 일부 자재사용에서 현재 BOM을 사용한다. 기록일치는 당시 생산 차감 완전성/실물 현재고를 보장하지 않는다. 전수 실측, scheduler, 운영 DB 변경은 포함하지 않으며 TODO011 전체 완료를 의미하지 않는다.
