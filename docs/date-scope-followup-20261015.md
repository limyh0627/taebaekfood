# 날짜 표시와 과거 전표 조회 후속

이번 묶음은 표시·읽기 경계의 독립 원인 세 건이다. 한국 새벽의 세금계산서 월·날짜가 UTC로 판독되는 문제, 주문 작업줄에서 ISO 출고 시각을 하루 앞당겨 임박으로 표시하는 문제, 회사 조건 없는 과거 전표 조회가 권한에 거절되고 사용자에게 이유를 알리지 않는 문제를 보완한다.

## 날짜 표시

TaxStatement 초기 선택월·현재 월 옵션은 기존 `today`로 읽고, 저장된 발행 시각과 과거 조회 시작일은 `dateOfLocal`로 읽는다. 과거 12개월 계산과 자료가 있는 최신 월로 이동하는 기존 정책은 유지한다. OrdersList의 작업줄 임박 판정도 같은 공용 날짜 판독을 사용하며 오늘·내일까지 임박, 완료 줄 제외 기준을 유지한다. 날짜 저장·정렬·수량·금액은 바꾸지 않는다.

## 회사별 과거 조회

기존 `fetchDateRange`는 회사 조건을 자동 추가하지 않는다. 호출의 다섯 번째 인수에 명시적인 현재 회사 조건을 전달한다. 공용 서비스와 Rules는 바꾸지 않는다. 실제 로그인 UID의 변경을 구독하고, 과거 조회마다 회사·UID·요청 세대를 확인한다. 현재 scope에 맞는 결과만 병합하고 회사 전환·재시도·화면 종료 뒤 늦은 결과를 반영하지 않는다.

과거 조회가 실패해도 최근 실시간 자료는 유지한다. 사용자에게 실패를 표시하고 읽기 전용 다시 불러오기 행동을 제공한다. 기존 live 우선 중복 제거와 회사 필터를 유지하며 발행 대기 요청·수동 선택·작성 초안을 조회 초기화에 묶지 않는다.

## 검증과 기록 경계

제품은 TaxStatement와 기존 시험, OrdersList와 기존 activeDates 시험의 네 파일이다. 문서는 이 파일·할일 목록·옛 전표 첫 저장 이력과 실제 적용 후 DB 변경 기록의 네 파일이며 인덱스 설정 한 파일을 포함해 총 아홉 파일이다. 한국 월초·연초, ISO와 날짜 문자열의 판독 동치, 회사·UID 전환과 지연 응답, 실패 후 재시도, 기존 발행 대기 보존을 직접 검증한다. 실제 Rules SDK는 검수용 자료만 사용해 무회사 조회 거절과 자기 회사 조회 성공을 확인한다.

시험·독립 검수·실제 화면·커밋·배포는 완료한 단계만 추가 기록한다. 운영 자료는 변경하지 않는다. 옛 tsx import 문제는 `6faf95c`로, 첫 저장 수정은 `0e90c56`과 후속 배포로 완료됐으므로 미완료 목록에서 제거한다. 원본 TODO 완료 수는 이번 부분 보완으로 늘리지 않는다.

Orders 작업줄의 실제 컴포넌트 8개 시험을 통과했다. UTC 절단으로 되돌리는 변이는 이틀 뒤 한국 날짜를 임박으로 잘못 표시하는 회귀 1개에서 실패했고 원본 바이트 복원 후 통과했다. 기존 hook 수명 수정과 다른 한 줄의 날짜 판독만 변경했다.

현재 Rules 원문을 별도의 검수용 프로젝트 namespace에 적용하고 실제 Auth·Firestore SDK로 조회 경계 3사례를 확인했다. 회사 조건 없는 날짜 조회는 권한 거절, 본인 회사 조건은 본인 회사 자료만 반환, 다른 회사 조건은 권한 거절이었다. 자기 문서 2개와 자기 UID를 정리했으며 운영 조회·운영 Rules 변경은 없다. 제품 호출의 회사 조건 전달은 별도 컴포넌트 회귀로 확인한다.

Tax 최종 26개와 Orders 8개로 고유 2파일 34개 시험이 통과했다. 이전 상태 setter가 발행 성공 경로에 남은 문제를 최종 검수에서 발견해 배포 전에 보완했고, 실제 성공 후 과거 행의 발행 표시·다음 요청 revision·선택 해제·오류 안내 없음까지 직접 검증했다. 날짜·회사 조건·늦은 응답·옛 setter 변이는 각각 해당 회귀가 검출했으며 원본 바이트로 복원했다. 최종 앱 타입과 별도 독립 검수가 통과했다. 인증 A→B→A 중 이전 발행 성공·오류·finally가 현재 선택·대기 정보·진행 상태를 바꾸지 못하도록 보완했다. 조회 재시도는 정상 발행 응답을 무효화하지 않는다. 추가 보호 제거 변이 2개도 검출했다. 보완 뒤 양 앱 빌드가 통과했다(관리자 21.07초·직원 14.71초, PWA 포함). 최종 148파일 manifest를 보존했고 FCM 원문을 복원했다.

운영 인덱스 메타데이터와 회사·거래일 조건의 이름만 최대 한 건 읽는 쿼리를 별도로 확인했다. 문서 ID·본문을 저장하지 않았으며 쿼리는 `FAILED_PRECONDITION`으로 필요한 인덱스가 없음을 응답했다. 현재 운영 READY 인덱스 9개와 로컬 설정이 일치하고, `issuedStatements`의 `companyId ASC / tradeDate ASC` 인덱스 하나만 추가했다. 원래 9개와 fieldOverrides는 보존한다. 인덱스는 별도 커밋 `de79f149`로 배포했고 2026-10-14T18:23:14.821Z에 READY를 확인했다. 18:26:38.402Z에 같은 이름 전용 최대 1건 조회가 HTTP 200으로 성공했다. 실제 업무 자료와 Rules는 변경하지 않았다. 앱 Hosting은 최종 화면·빌드 검수 후 배포한다.

총괄의 실제 화면 검수에서도 한국 1월 1일 00:30의 2026년 1월 선택, 회사 A→B→A의 이전 회사 응답 무시, UID A→B→A의 이전 계정 응답 무시를 확인했다. 현재 조회 오류의 안내와 다시 불러오기 버튼을 사용해 과거 목록이 복구됐다. 실제 작업순서 줄에서 ISO·날짜 문자열의 이틀 뒤 주문은 임박이 없고 내일·오늘·지난 날짜는 임박으로 표시됐다. 모두 운영 연결을 차단한 합성 자료이며 UI 조작으로 운영 전표를 발행하지 않았다. 증거는 저장소 밖 `records/tax-history-retry-synthetic-20261015.png`와 `records/order-due-date-synthetic-20261015.png`다.

추가 인증 보호의 최종 화면 검수에서도 같은 실행 안의 인증 B→A 뒤 늦은 발행 성공·오류가 현재 1건 선택과 10,000원 합성 초안을 유지함을 확인했다. 사진은 저장소 밖 records/tax-auth-ack-synthetic-20261015.png이며 실제 업무 전표가 아니다.
