# 품목 연결 문제 확인과 선택 정리

014 후속이다. 현재 품목 목록으로부터 화면을 만들면 보관됐거나 목록에 없는 품목의 거래처 연결은 사용자에게 보이지 않는다. 기존 전체 연결 교체 콜백으로 이를 정리하면 동시에 추가된 연결까지 삭제할 수 있어, 정확한 한 건을 처리하는 별도 경로가 필요하다.

목록은 현재 회사가 명시된 연결만 보여 준다. 보관 품목, 현재 목록에서 확인하지 못한 참조, 회사 관계 불일치를 구분한다. 목록에 없다는 이유만으로 삭제된 품목이라고 확정하거나 다른 회사의 품목·거래처 이름을 노출하지 않는다. 과거 조사에서 언급한16건을 이번에 다시 조회하거나 원품목을 확정한 것은 아니다.

정리 전 서버가 해당 연결과 참조 품목을 확인하고 연결의 나노초 변경 버전을 반환한다. 삭제는 서버에서 품목의 실제 부재를 확인한 연결로 한정한다. 보관 품목은 나중에 재사용할 수 있으므로 목록에 보여 주되 연결을 유지한다. 사용자가 확인한 연결 한 건의 버전·회사·작업 번호를 고정하고, 서버 트랜잭션에서 다시 검사한 뒤 그 연결만 삭제한다. 원문과 처리 결과는 서버 전용 영수증에 남긴다. 현재 품목이 확인되거나 연결이 변경·재생성됐으면 새 확인을 요구하며 다른 연결 전체를 다시 저장하지 않는다.

응답을 받지 못한 경우 결과 확인·같은 최초 요청 재시도·미처리 요청 중단을 제공한다. 결과가 없다는 것만으로 미처리를 확정하지 않는다. 중단은 늦게 도착할 같은 요청도 봉쇄한다. 성공한 삭제를 복원하거나 원품목을 추정해 자동 재연결하지 않는다. 원문 손상이 있어도 정확한 작업 참조로 결과 확인과 미처리 요청 중단에 진입할 수 있어야 한다.

서버 명령은 구현을 동결했다. 집중5개·실제 Firestore/Admin SDK와 Rules13개, 총18개를 통과했다. 서버 변경 버전 비교와 중단 봉쇄를 각각 제거한 변이에서 실패를 검출하고 원문을 복원했다. 서버 타입 검사·빌드도 통과했다. Rules는 자기 UUID 프로젝트에만 적용하고 자체 합성 자료를 정리했으며 공유 프로젝트를 변경하지 않았다. 실제 Auth 로그인·HTTP callable 호출은 이번 시험 범위 밖이며 합성 권한의 Rules 검사·서버 함수 직접 실행과 구분한다.

화면·클라이언트 구현을 동결했다. 신규 목록·복구 화면13개와 서비스10개, 기존 분류·BOM 등7개를 더해30개 집중 시험을 통과했다. 목록 회사 보호와 서비스의 늦은 응답 보호를 제거한 변이에서 각각 실패를 검출한 뒤 원문을 복원했다. 관리자 연결은 기존 전체 해제 대신 정리 성공 후 정적 자료 재조회만 전달한다. 거절된 요청은 명시적으로 중단을 선택해 확정 거절 결과를 확인한 뒤 사본을 정리하고 새 서버 확인을 시작한다.

서버·UI12파일의 독립 검수에서 미해결 P1/P2가 없음을 확인했다. 같은 묶음의 앵커27개를 포함한 고유 관련 시험은75개다. 재실행과 보강한 기존 시험을 중복 합산하지 않는다. 최종 앱 타입·서버 빌드·양 앱 빌드와 사전 검증을 통과했다. 실제 운영 연결 삭제는 하지 않았으며 합성 자료로 검증했다.
