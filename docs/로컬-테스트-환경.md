# 주문·배송 로컬 테스트 환경

운영 Firebase와 분리된 `demo-taebaekfood-local` 전용 환경이다. 앱은 `VITE_USE_FIREBASE_EMULATORS=true`일 때 `demo-` 프로젝트 ID와 `127.0.0.1` 또는 `localhost`만 허용한다. 조건이 다르면 앱 시작 단계에서 중단한다.

## 실행 순서

Java 21을 사용할 수 있는 터미널에서 아래 세 작업을 실행한다.

1. `npm run emulators:local` — Authentication 9099, Firestore 8082, Storage 9199, 관리 화면 4000.
2. `npm run seed:local` — 에뮬레이터 데이터만 초기화하고 가상 데이터 40건을 넣는다.
3. `npm run dev:local` — 관리자 이식본을 8081에서 실행한다. 직원 이식본은 `npm run dev:local:staff`로 8083에서 실행한다.

로그인 화면의 `테스트 관리자 바로 접속`을 사용한다. 직접 입력할 때는 `testadmin` / `localtest`이다. 화면 상단에 `로컬 테스트 · 운영 DB 미연결`이 항상 보여야 한다.

## 포함된 검수 사례

- 일반·스마트스토어·택배 가상 거래처와 연결 품목이 없는 거래처
- 대기중·작업중·작업완료·출고완료·보류 주문
- 낱개, 별도 박스 재고 상품, 포장 환산 상품
- 병·뚜껑·라벨·박스·테이프와 원료가 연결된 BOM
- **전표** — 매입처(`가상부자재상사`)와 매입 연결 품목(병·뚜껑), 계정과목 다섯(500·505·800·108·251)

  전표를 로컬에서 보려면 이 셋이 다 있어야 한다(2026-09-13에 보태다).
  매입처가 없으면 매입전표 창이 아예 안 열리고, 계정과목이 없으면 줄마다 골라야 하는 계정
  고르개가 비어 있어 "계정과목이 설정되지 않았습니다"에서 영영 막힌다.
- archived 품목 제외 확인
- 라벨, 제조일, 팔레트, 송장출력, 작업 확인 데이터

`seed:local`은 매번 로컬 에뮬레이터 자료를 지운 뒤 같은 자료를 다시 만든다. 운영 DB와 배포 대상에는 쓰지 않는다.
