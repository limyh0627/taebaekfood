# 상품 매입 입고와 수량 로트의 연속 처리

## 문제

상품은 출고 때 수량 로트를 차감하지만 발주 입고 확정은 완제품·반제품에만 로트를 만들었다. 상품 입고는 숫자 재고만 늘어나 이후 출고의 로트 부족을 만들었다. 부자재는 숫자 재고만 처리하라는 사용자 지시를 유지한다.

## 수정 범위

기존 생산 분류 `holdsUnitStock`의 의미를 바꾸지 않는다. 별도 공용 `tracksQuantityLots`로 입고·출고 로트·반품·상품 재고 표시를 연결한다. 상품 자체의 수량 재고와 로트 잔량은 같은 입고 단위이며, 중량을 사용해 주문 수량이나 입고 수량을 다시 환산하지 않는다. 개수 상품은 기존 공용 함수가 해석하는 등록 규격·BOM·포장 중량을 유지한다. kg 상품은 재고 1단위 자체가 1kg이며 포장 규격 무게를 다시 곱하지 않는다. L 상품은 명시 등록된 유효한 밀도만 중량 근거로 쓰고, 밀도를 포장 무게로 추정하지 않는다. 중량 근거가 없으면 중량 메타데이터를 0으로 둔다. 이 선택도 앱 입고와 서버 반품이 같은 공용 함수를 사용한다. 기존 로트의 저장된 중량은 자동 수정하지 않는다.

명시된 원료 연결을 가진 기존 매입 SKU와 벌크 원료는 기존 원료 로트 경로를 유지한다. 이름이 원료와 같다는 이유만으로 상품 재고를 원료 홀더에서 파생 표시하지 않는다. 부자재의 기존 로트 자료는 임의 삭제하지 않으며 신규 입고·출고에서는 수량 재고만 처리한다.

상품 매입 입고는 품목 재고·입고 로트·입고 기록·발주 상태를 한 거래로 확정한다. 같은 입고 번호로 재시도하면 재고와 로트를 다시 늘리지 않는다. 상품 출고의 기존 FIFO와 원로트 복원 계산을 재사용한다. 새 로트 때문에 상품 반품을 거절하지 않도록 서버 반품 분류와 계획도 같은 공용 판정을 사용한다.

## 검증과 배포

실제 직원 SDK로 매입 입고 8+15, 출고 20의 여러 로트 FIFO, 출고 원복, 중복 입고, 부자재 수량 처리, 타회사 거절과 원자 실패를 확인한다. 서버 상품 반품 양방향과 명시 원료 매입 SKU의 기존 경로를 대조한다. 중첩 배열 오류로 실패한 신계약 원문 재개도 별도 회귀로 확인하고 구형 계약을 자동 승격하지 않는다.
