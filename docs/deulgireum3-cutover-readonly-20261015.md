# 시골향 들기름③ 최신 이관 계획 확인

현재 단계는 읽기 전용 도구 준비다. 운영 조회·적용은 아직 실행하지 않았다. 코드 배포와 운영 자료 변경 승인을 구분하며, 과거 계획의 품목·일지 건수와 원가·kg 수치를 현재 결과로 재사용하지 않는다.

## 범위

고정 프로젝트의 기본 DB에서 태백 회사 조건으로 `items`, `productionSalesLogs`, `item_bom`, `item_formula` 전체 원문과 기존 도구가 지정한 BOM 한 건의 존재를 읽는다. 다른 회사·주문·실제 원장으로 조회를 확대하지 않는다. 최신 일지까지 읽은 뒤 계획기에서 9월 28일 경계를 판정한다.

새 순수 계획기는 품목 분류·기존 이력·캔 제외·BOM·생산행 이동의 기존 규칙을 확인하고, 원가·배합·서류 환산에는 기존 공용 함수를 사용한다. 수동 원가나 기존 ③ 묶음, 이력·BOM의 충돌, 해석할 수 없는 형식은 추정해 덮어쓰지 않는다. 서류 환산상 kg 변화는 실제 재고나 원장 정정 결과를 의미하지 않는다.

## 실행 경계

옛 정정 스크립트는 import·실행·편집하지 않는다. 새 CLI에는 적용·복원 쓰기 경로를 두지 않고, 쓰기 옵션·알 수 없는 인자·중복 인자는 인증과 통신 전에 거절한다. 기존 공식 CLI 인증을 재사용하며 원문이나 인증 정보를 콘솔에 출력하지 않는다.

조회 원문과 문서 버전·조회 시각, 계획과 입력 해시, 계산 소스·의존 파일 해시는 덮어쓰기 없는 비공개 파일로 보존한다. 여러 조회의 결과이므로 원자 스냅샷으로 설명하지 않는다. 실제 읽기는 도구 검수 뒤 지정한 범위로 수행하며, 운영 적용은 새 결과에 대한 사용자 승인과 별도 실행 설계가 필요하다.

완전하게 읽고 검증한 원문에서 업무 충돌이 발견되면 원문과 구조화된 차단 사유를 보존하고 `plan`과 `planHash`는 `null`로 둔다. 공개 출력은 사유별 건수만 제공한다. 인증·조회 미완료·형식 오류를 완전한 스냅샷으로 저장하지 않는다. 재계획은 새 전체 조회와 `work` 하위의 새 명시 출력 이름을 사용하며 기존 결과를 덮지 않는다.

공용 함수 교차검증에는 실제 품목과 명시적 단위 입력의 단위수량 투영, 날짜별 품목 판독, 저장 판매행의 전후 서류 환산을 사용한다. 판매행을 가짜 품목으로 바꾸거나 단위수량 시험을 실제 판매량으로 설명하지 않는다.

## 검증 및 현재 결과

구현·시험·독립 검수와 실제 읽기 결과는 완료되는 단계별로 아래에 기록한다. 현재 적용 건수는 0이다.

초기 후보는 구현 담당의 관련 시험 33개(순수 계획 12개·CLI 21개), 기존 이력 보호와 소스 SHA 보호 변이 2종, 좁은 타입 검사, 실제 Node 22 자체검증이 통과했다. 독립 검수에서 원문 숫자 `-0`의 JSON 왕복 손실 가능성을 발견해 일반 문서와 고정 BOM의 사전 거절·회귀를 당시 보완 중이어서 실행 준비 완료 판정을 보류했다. 자체검증은 인증·운영 조회·운영 출력 파일 생성을 수행하지 않는다. 옛 도구는 실행하지 않고 순수 반복문 두 곳만 AST로 추출해 합성 자료의 patch 동치를 확인했다.

업무 충돌은 처음 확인한 사유를 보존하고 전체 계획을 비운다. 모든 충돌을 전수 열거한 결과로 설명하지 않는다. 저장된 판매·추가 행의 서류 배합 변화와 실제 품목/BOM의 단위수량 투영도 각각 구분한다. 운영 조회 전에는 도구 검수와 실제 진입점 검증을 구분해 완료한다.

원문 보존 보완 후 관련 시험은 38개다. 일반 문서·고정 BOM 응답·최종 결과의 세 경계에서 JSON 왕복의 깊은 동치를 확인해 손실을 파일 생성 전에 거절한다. 추가 보호 변이도 검출하고 복원했으며, 좁은 타입과 Node 22 자체검증을 통과했다. 신규 4파일의 독립 검수는 CLEAR다.

독립 담당이 실제 Node 22 진입점의 자체검증 성공과 적용·복원·알 수 없는 인자·중복 인자 네 경우의 인증 전 거절을 확인했다. 다섯 경우 모두 인증·외부 통신·운영 출력은 0이며 기존 158파일과 FCM 원본도 보존됐다. 계측 중 발생한 tsx의 로컬 named pipe 시도는 외부 통신과 구분하고 계속 차단했다. 운영 읽기와 실제 계획 파일 생성은 아직 실행하지 않았다.
