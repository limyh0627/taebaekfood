# 시골향 들기름③ 최신 이관 계획 확인

읽기 전용 도구를 검증하고 최신 운영 자료를 조회했다. 이미 ③으로 반영된 형태를 확인했으므로 추가 적용은 필요하지 않다. 이번 작업에서 운영 자료는 변경하지 않았다. 과거 계획의 품목·일지 건수와 원가·kg 수치를 현재 결과로 재사용하지 않는다.

## 범위

고정 프로젝트의 기본 DB에서 태백 회사 조건으로 `items`, `productionSalesLogs`, `item_bom`, `item_formula` 전체 원문과 기존 도구가 지정한 BOM 한 건의 존재를 읽는다. 다른 회사·주문·실제 원장으로 조회를 확대하지 않는다. 최신 일지까지 읽은 뒤 계획기에서 9월 28일 경계를 판정한다.

새 순수 계획기는 품목 분류·기존 이력·캔 제외·BOM·생산행 이동의 기존 규칙을 확인하고, 원가·배합·서류 환산에는 기존 공용 함수를 사용한다. 수동 원가나 기존 ③ 묶음, 이력·BOM의 충돌, 해석할 수 없는 형식은 추정해 덮어쓰지 않는다. 서류 환산상 kg 변화는 실제 재고나 원장 정정 결과를 의미하지 않는다.

## 실행 경계

옛 정정 스크립트는 import·실행·편집하지 않는다. 새 CLI에는 적용·복원 쓰기 경로를 두지 않고, 쓰기 옵션·알 수 없는 인자·중복 인자는 인증과 통신 전에 거절한다. 기존 공식 CLI 인증을 재사용하며 원문이나 인증 정보를 콘솔에 출력하지 않는다.

조회 원문과 문서 버전·조회 시각, 계획과 입력 해시, 계산 소스·의존 파일 해시는 덮어쓰기 없는 비공개 파일로 보존한다. 여러 조회의 결과이므로 원자 스냅샷으로 설명하지 않는다. 실제 읽기는 도구 검수 뒤 지정한 범위로 수행하며, 운영 적용은 새 결과에 대한 사용자 승인과 별도 실행 설계가 필요하다.

완전하게 읽고 검증한 원문에서 업무 충돌이 발견되면 원문과 구조화된 차단 사유를 보존하고 `plan`과 `planHash`는 `null`로 둔다. 공개 출력은 사유별 건수만 제공한다. 인증·조회 미완료·형식 오류를 완전한 스냅샷으로 저장하지 않는다. 재계획은 새 전체 조회와 `work` 하위의 새 명시 출력 이름을 사용하며 기존 결과를 덮지 않는다.

공용 함수 교차검증에는 실제 품목과 명시적 단위 입력의 단위수량 투영, 날짜별 품목 판독, 저장 판매행의 전후 서류 환산을 사용한다. 판매행을 가짜 품목으로 바꾸거나 단위수량 시험을 실제 판매량으로 설명하지 않는다.

### 고정 범위 실제 조회와 판독 결과

확장 도구는 기존 22개와 신규 6개를 합한 관련 시험 28개, 소모 내역 없는 대상 누락 방지의 의미변이 검출·원복, 좁은 타입 검사, 실제 Node22 진입 및 설계·독립 변경분 검수를 통과했다. 등록한 추가 10일의 실제 읽기 1회가 종료 0으로 완료됐으며 9월 28일 파일럿은 검증 후 당시 관측으로 재사용했다.

고정 11일의 날짜 범위 목록 120건에서 직접 대상 태백 고유 주문은 12건이었다. **원장 연결 56건은 주문 수가 아니라, 대상 주문의 저장 소모 내역을 operationId별로 묶어 실제 원장과 대조한 그룹 수**다. 연결이 있는 주문은 10건이고, 나머지 2건은 저장된 소모 내역이 없어 도구가 `stored-trace-missing`으로 분류했다. 범위 선정에서 제외한 목록 108건을 연결 실패로 세지 않는다.

소모 내역 없는 10월 1일·10월 13일의 두 주문은 저장 근거상 생산 증가 없이 기존 완제품 로트를 출고한 형태였다. 두 건 모두 저장 생산량·생산 재고증감·원료 소비 및 원료 원장 ID 배열이 비어 있고, 주문 품목과 일치하는 출고 재고감소 및 완제품 로트 소비 기록은 있었다. 이는 엔진의 완제품 재고 충당 분기와 일치한다. 따라서 이 두 건을 원료 누락 오류라고 해석하지 않는다. 한 건의 생산기록 포인터는 주문수량 기반 서류 연결이라 실제 생산량 증명이 아니다. 당시의 명시적 재고 사용 선택이나 실물 상태까지 복원한 것은 아니다.

별도 담당이 비공개 원문만으로 대상 선정·원장 연결·소스 18개·기존 근거 및 파일럿 SHA·관측 원문 해시·집계를 재계산해 일치를 확인했다. 최종 주문 12건의 전체 typed 원문과 버전이 같았고 중복 주문 관측은 없었다. 전체 관측 GET 180건은 원문 응답 68건·정형 404 본문 112건이며 선행 파일럿을 포함한 수치다. 새 10일의 고유 단건 관측은 162건이었고 실제 캐시 재사용은 없어 캐시 재사용 동작을 운영에서 실증했다고 하지 않는다. 서버의 소수 6자리 시각과 GET의 클라이언트 관측시각을 구분해 보존했다.

새 비공개 `work/deulgireum3-order-links-related-days-20261015.json`은 14,230,125bytes이며 SHA256은 `AE449A3C5BA34EA4B59696179E77D63A301F44E59FBB4495B569D9826E910B2B`, 관측 원문 해시는 `4336FD31271C835C9C171DA071E5185A0AD5B2DC229ABAD68B00433A76D1DB24`다. 기존 두 비공개 결과는 보존했다.

고정 11일·명시 32개 품목의 직접 대상 주문에 대한 현재 저장 연결 확인은 이 범위로 마감한다. 이관 전 백업·감사 근거 없이 적용자·과거 이관 무손실·실물 재고 정합을 더 확대하여 주장하지 않는다. 세트 구성과 비표준 과거 날짜 등 범위 밖은 별도이며, 이번 모든 단계에서 운영 쓰기·앱 화면·원료 자동 계산 변경은 없다.
