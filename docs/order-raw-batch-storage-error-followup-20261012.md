# 주문 원료 일괄 저장의 중첩 배열 오류

2026-10-12 운영 읽기에서 이용현(스마트) `ORD-261012-005`와 짠지네식품 `ORD-261012-008`의 실패 원문을 확인했다. 두 작업은 모두 `raw-inventory` 단계에서 Firestore의 `Nested arrays are not supported` 오류로 실패했다. 원료 부족 판정과 구분한다.

## 원인과 수정

최초 예약 계획은 Map을 배열 쌍으로 보존한다. 이 예약 계획을 포함한 요청 객체 전체를 Firestore 문서에 직접 넣어 SDK가 거절했다. 새 작업 문서는 최초 요청을 정규화된 JSON 문자열 `requestText`로 저장한다. 원래 요청, 요청 지문, 날짜, 계정, 명령, 계산 방식은 바꾸지 않는다.

공용 판독 함수는 새 문자열과 기존 요청 객체를 검증해서 읽는다. 두 표현이 함께 있으면 내용이 같아야 한다. 현재 원료 완료 근거와 이전 생산기록 완료 근거가 모두 이 함수를 사용한다. 기존 문서를 일괄 변환하지 않는다.

주문 카드와 복구 안내는 공용 한국어 표시 함수로 기술 오류를 변환한다. 원래 오류 기록과 서버 복구 판정은 유지한다. 영어 문구를 숨긴 것을 재고 미반영이나 잠금 해제 가능 판정으로 사용하지 않는다.

## 재발 방지 검증

기존 실제 직원 SDK 시험은 예약 계획이 빠진 단순 요청을 사용했다. 실제 엔진이 만든 것과 같은 네 가지 예약 Map 배열을 포함해 최초 저장, 같은 요청 재개, 생산기록 저장 및 이전 완료 근거 판독을 검증한다. 보호 코드를 제거하는 변이가 시험에서 실패해야 한다. 전체 회귀, 타입 검사, 양 앱 빌드와 실제 한국어 카드 표시도 확인한다.

## 검증 결과

- 전체 회귀: 528파일, 4,803시험 통과, 7건 건너뜀, 실패 0. `localtest` 모드, 운영 연결 없이 실행했다.
- 실제 엔진 예약 함수에서 만든 중첩 배열을 포함한 직원 Auth·Firestore SDK 18시험과 집중 48시험 통과. 생성한 합성 문서와 계정은 정리 후 부재를 확인했다.
- 저장 형식을 되돌리는 변이는 실제 중첩 배열 오류로 실패했고, 이전 작업 판독을 제거하는 변이도 실패했다. 한국어 표시 제거 변이는 13시험 실패로 검출했다. 변이 후 원본 시험을 다시 통과했다.
- 관리자·직원 앱 타입과 빌드 통과. 필드 사전 자체 검사 및 `check-only` 통과.
- 실제 주문 카드·복구 패널을 합성 입력으로 브라우저에서 확인했다. 내부 SDK 오류와 복구 코드가 한국어로 표시되고 기존 재고 부족 설명은 유지된다. 합성 복구 버튼은 잠금을 유지하며 운영 연결이나 저장을 수행하지 않는다.

운영 읽기에서 두 주문의 해당 출처 원료 작업·수불부·주문 상태 감사·생산기록은 조회되지 않았다. 부재만으로 모든 효과가 없거나 잠금을 해제할 수 있다고 단정하지 않는다. 운영 재고·로트·주문·잠금은 이 코드 수정에서 변경하지 않는다. 이용현 실패는 생산기록 계약 표시가 없는 이전 작업이고 짠지네 실패는 해당 표시가 있는 작업이므로, 두 주문의 재개 가능 여부를 같은 것으로 단정하지 않는다.

## 배포

소스 `fe1f8cfa749b30531e147f75aa2e6fd8f901d2c6`의 정확한 15파일을 main에 통합하고 GitHub에 푸시했다. 관리자·직원 Hosting 배포는 모두 성공했다. 검증된 빌드를 그대로 사용했고 배포 과정에서 다시 빌드하지 않았다. 총괄이 공개된 137개 파일의 SHA가 로컬 빌드와 일치함을 확인했다.

Functions·Rules·운영 재고·로트·주문·잠금은 변경하지 않았다. 짠지네는 새 생산기록 계약이 있는 동일 작업 재개 경로의 저장 오류를 고쳤다. 이용현의 이전 계약 작업 잠금은 별도 복구 과제로 남아 있다. 화면 표시 개선과 운영 잠금 해제를 구분한다.
