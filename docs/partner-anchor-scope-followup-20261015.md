# 거래처 연말 앵커 범위 검증

043 후속이다. 앵커 문서 경로가 회사·연도에 맞아도 기존 본문의 회사·연도·기준일이 다르면, 그대로 백업해 덮거나 되돌릴 때 다른 범위 원문을 보존·복원할 수 있다. 운영에서 이런 문서를 발견했다는 주장이 아니라 기존 코드의 검사 공백을 보완한다.

계획 준비·계획 검사·적용·적용 결과 확인·조건부 되돌리기에서 문서 경로와 본문 범위를 대조한다. `companyId`, `year`, `asOf`가 필요한 범위와 일치해야 한다. 별도로 저장하지 않는 기존 `id` 필드는 생략할 수 있지만 명시돼 있다면 경로와 같아야 한다. 기존 문서가 없는 경우는 정상이다.

범위 필드가 없는 옛 문서는 값을 추정해 채우지 않는다. 어떤 필드가 없거나 다른지, 원문 백업과 회사·연도·기준일 근거를 확인한 뒤 계획을 다시 만들어야 한다는 안내를 제공한다. 정상 기존 문서·빈 앵커의 적용, 중복 실행, 원자료 변경 차단과 조건부 되돌리기는 유지한다.

구현을 동결하고 합성·Node21개와 실제 Admin SDK6개, 총27개 관련 시험을 통과했다. 범위 비교를 제거한 의미변이에서7개 실패를 검출하고 원문을 복원했다. 좁은 타입 검사와 diff 검사를 통과했다. SDK는 자체 UUID 프로젝트의 합성 자료만 사용했고 생성한 자료를 정리한 뒤 각 컬렉션이 비었음을 확인했다. 앞선 SDK 비활성 실행과 최종 실행을 중복 합산하지 않는다. 독립 검수에서 미해결 P1/P2가 없고 동결 원문과 검증 근거가 일치함을 확인했다.

이번 도구 보완은 같은 묶음의 `b477c721f751d98f35fa5973a71945453bf1bb5f`로 main에 반영했다. 앱과 서버 배포 근거는 [연결 정리 후속](partner-item-reference-recovery-followup-20261015.md)의 마감 기록에 있다. 이 명령 도구는 운영에서 실행하지 않았다. 2026년 결산은 아직 도래하지 않았으며 이번에는 운영 계획 준비·적용·되돌리기를 하지 않았다. 과거 연도의 합성 자료만 사용했고 실제 결산 적용은 남겨 둔다.
