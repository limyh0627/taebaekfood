## 1. #2 원료 재고 단일 소스 (가장 중요)

### 문제
- 재고 화면이 `item.stock`(로트 합계의 **미러 값**)을 읽음. 어딘가에서 stock을 직접 건드리면 실제 로트(lots)와 어긋남.
- 실제 사례: **검정깨** 화면엔 0으로 뜨는데 실제 로트에는 80kg 보유. (예전 깨분참기름 "화면 0" 사건과 동일 계열)

### 원인
- 원료(raw)는 `lotRaw.id === product.id`라 캔/반제품 파생 로직을 안 타고 곧장 `product.stock`을 표시·필터·정렬에 사용.

### 변경 내용 (`components/ItemList.tsx`)
- 모듈 헬퍼 **`displayStockOf(p)`** 신설: 원료이고 로트가 있으면 `lotStockInUnit(lots, 원료명)`(운영단위=기름은 L로 환산), 로트 없는 원료(예: 깻묵)나 완제품/상품은 기존 `stock` 폴백.
- 적용 지점: 재고표 숫자·편집 시드값, 발주 draft/확장 라벨의 "현재 재고", `재고 있는 것만`·`재고 부족만` 필터, 정렬의 부족 판정.

### 효과 / 검증
- DB 실측으로 확인: 오일류 kg→L 환산이 stock과 일치(깨분참기름 1152.76≈1152.8, 통깨참기름 450=450, 생들기름 918=918 등), **드리프트건 교정**(검정깨 0→80, 참깨 960→975), 로트 없는 깻묵은 6000 유지(회귀 없음).
- 이제 stock 필드가 무엇이든 **로트가 유일 기준** → "화면만 0" 버그 근절.

### 남은 것
- item.stock 필드 자체는 여전히 동기화 저장됨(다른 화면 호환). 완전 제거는 후속.

## 2. #1 로트(lot) 무한 증가 방지

### 문제
- 소진된 로트를 삭제하지 않고 `status:'depleted'`로 계속 보존. 원료 재고가 `item.lots` **배열 필드**라, 몇 달 쌓이면 배열이 수백~수천 개 → 품목 읽을 때마다 죽은 로트까지 로드(비용·속도), Firestore 1MiB 한도 위험.

### 변경 내용
- `src/shared/lotUtils.ts`: **`pruneDepletedLots(lots, retentionMonths=6)`** 추가 — active는 항상 보존, depleted는 `receivedDate`가 6개월 이전이면 제거. 변화 없으면 원본 반환.
- `src/shared/services/firebaseService.ts`: **모든 로트 쓰기가 지나는 `mutateRawMaterialLots`** 트랜잭션에서 저장 직전 `pruneDepletedLots` 적용. (입고·재고조정·반품·정정·주문차감 전 경로 자동 커버)

### 효과
- 로트 배열 크기가 **최근 6개월치로 자동 상한**. 소비 이력은 주문의 `rawConsumedLots` 스냅샷에 별도 보존되므로 **추적성 손실 없음**.
- 현재 배열은 작아(품목당 1~2개) 즉각 변화는 없고, **향후 누적을 원천 차단**.

## 3. #5 로트 역추적(리콜)

### 문제
- 정방향(제품 → 투입 원료 로트)만 있고, **"이 로트가 들어간 제품/주문 전부"**(리콜용 역방향)는 못 뽑았음.

### 변경 내용 (`components/ProductionManager.tsx`)
- 생산실적 화면에 **"로트 역추적 · 리콜"** 접이식 패널 추가.
- 원료명·공급처·로트번호로 검색 → 그 로트가 투입된 **주문(거래처·납품일·투입량)** 목록과 총 투입 kg 표시.
- 데이터는 주문 문서의 `rawConsumedLots` 스냅샷을 **재사용(추가 읽기 0)**. 로트 단위로 그룹핑(lotId 우선, 없으면 원료|공급처|로트번호 키).

### 효과 / 한계
- 원료 로트에 문제가 생기면 **어느 거래처의 어느 납품 건에 들어갔는지 즉시 확인** → 리콜 대응 가능.
- 범위는 **현재 로드된 주문 기준**(최근+불러온 과거). 전체 이력 대상 조회가 필요하면 후속으로 주문에 `consumedLotIds` 평면 배열 + array-contains 쿼리를 추가하면 됨(패널 문구에 명시).

## 4. 당일 추가 처리 (버그·정리)

### #15 partner_item 스키마 통일
- 레거시 임포트 네이밍(`Item_ID`/`Partner_ID`/`Standard_Price`/`item_id`/`customer_id`) → canonical `itemId`/`partnerId`/`price`.
- write 경로(upsert/링크쿼리/품목병합)·Firestore `where()` 쿼리 정규화, useAppData 로드 시 양쪽 형식 일관 주입으로 기존 read 157곳 무변경 호환.
- **DB 750개 문서** 백필 후 레거시 필드 삭제(검증: 레거시 0, itemId 결측 0).

### 버그 수정
- **매입전표 품목 누락**: 한 품목에 매입처가 여럿이면 목록에서 빠지던 문제(단일 매핑 `psMap` → `partnerIn` 직접 조회).
- **전표 수정모드 이중 부가세차감**: 저장된 부가세포함 단가를 그대로 로드하도록 수정.
- **주문카드 품목추가 안 뜸**: `items`엔 없는 `partnerId`로 비교하던 완제품 필터를 `partnerItems`(거래처 연결) 기준으로 교체.
- **매출전표 진행주문에서 스마트스토어 거래처 제외**.
