# 재고·결산·과거 주문 연결 점검 후속

노션 원본 TODO011·043·017의 남은 조건에서 실제로 사용할 수 있는 읽기 도구를 보완했다. 전체 43개 중 21개 완료·22개 잔여를 유지한다. 실측 기준 확정, 실제 연말 결산 적용, 주문별 제외 사유 확인은 완료되지 않았다.

## 재고 일일 점검

기존 `npm run audit:daily`에 제품 원장과 현재 수량의 대조를 연결했다. 현재 재고를 읽은 날짜와 점검 대상 날짜를 구분한다. 회사 없는 공용 BOM·포장표는 해당 회사의 품목 ID로 연결한다. 실측 근거가 없는 앵커는 전산 기준으로 표시하며 계산값이 같다는 이유로 실물 재고가 맞다고 판정하지 않는다. 원료는 제품 원장으로 검증하지 않는다.

파일 모드는 인증 초기화 전에 실행하며 입력이나 기존 결과를 덮어쓰지 않는다.

```sh
npm run audit:daily -- --input 입력.json --output 새결과.json
```

## 연말 잔액 미리보기

기존 `stamp-partner-anchor.mts`가 반품 및 검증된 선급·선수 적용 기록을 실제 계산에 전달하도록 보완했다. 중복 전표 ID, 다른 회사의 원전표, 변조된 반품 증명, 불완전한 분개는 계산을 중단한다. 전체 조회 파일로 미리보기를 실행할 수 있으며 파일 모드의 적용·되돌리기는 허용하지 않는다.

```sh
npx --no-install tsx scripts/stamp-partner-anchor.mts --year=2026 --input=전체조회.json
```

파일 배열의 존재만으로 조회 범위·시점의 완전성을 입증하지 않는다. 생성자가 확인한 전체 조회 자료가 필요하다. 기존 온라인 적용·되돌리기의 익명 인증 및 순차 저장 방식은 이번 미리보기 검증으로 안전한 운영 실행이라고 주장하지 않는다. 실제 운영 결산은 실행하지 않았다.

## 과거 더미 전표 연결 진단

더미 문서의 실제 연결 주문만 읽으며 옛 스크립트의 대상 배열을 정답으로 추정하지 않는다. 회사·다른 전표 연결·기존 제외 값·사유 증거를 구분한다. 실제 연결 10건은 모두 존재했고 다른 전표 연결 충돌은 없지만, 개별 제외 사유가 없어 모두 보류했다. 자동 이관이나 더미 전표 삭제는 하지 않았다.

```sh
npx --no-install tsx scripts/read-dummy-order-exclusions.mts --read-only
```

운영 원문 보고서는 Git에서 제외되는 `work/`에만 저장한다. 여러 읽기는 원자적 스냅샷이 아니므로 이관 전 최신 원문·버전·전표 집합을 다시 확인해야 한다.

## 검증 상태

최종 회귀는 재고 8개·연말 계산 6개·주문 연결 6개로 서로 다른 20개가 통과했다. 기본 앱 검사에서 제외되는 도구 파일은 확장 설정으로 별도 타입 검사도 통과했다. 재고 파일 모드 및 연말 파일 미리보기는 실제 CLI로 실행했다.

실제 일일 점검은 처음에 품목 목록이 없는 과거 주문으로 중단됐다. 원문을 보존하면서 입력 오류로 분리하고 정상 입력의 점검을 계속하도록 수정한 뒤 재실행이 성공했다. 2026-10-10 13:08 KST 조회에서 태백은 주문 본문 없이 회사·출력 여부만 있는 문서 1건이 확인돼 541개 품목의 대조를 입력 미확인으로 표시했다. 풍회 6개 품목은 기준 없음 1개·원료 별도 대조 5개다. 문서가 생긴 원인이나 물리 재고의 정합성은 추정하지 않는다.

변경은 로컬 점검 도구에 한정한다. 앱·Functions·Rules 실행 소스는 바꾸지 않았으므로 제품 배포는 하지 않았다. 운영 문서 쓰기·GitHub 푸시도 실행하지 않았다. 운영 원문·개인 자료·비공개 보고서는 커밋하지 않는다.
