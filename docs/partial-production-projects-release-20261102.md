# 부분 생산·주문 분할·프로젝트 최종 묶음

상태: 로컬 구현 및 독립 검수 완료, 전체 통합시험·빌드·배포 검증 중. 운영 배포와 main 반영은 아직 완료하지 않았다.

주문 품목을 일부 수량만 완료하고 같은 생산에서 다른 품목의 재고를 추가할 수 있다. 카드에는 완료 수량과 주문 수량을 함께 표시한다. 완료량은 기존 재고 사용량과 실제 생산량을 구분하며, 추가 재고는 고객 청구 품목에 넣지 않는다. 주문 수정창의 분할은 완료 수량의 귀속을 이관하고 원료를 다시 차감하지 않는다.

생산 취소는 원래 생산 근거와 현재 완료 수량의 소유 주문을 검증해 전체 생산 효과를 한 거래로 되돌린다. 다른 주문의 예약분은 보호한다. 주문의 완료 배정 해제·미출고 주문 삭제는 물리 재고 취소와 구분한다. 출고·출고 취소·전표 발행도 같은 완료 근거를 검증한다. 전표 연결이나 확인할 수 없는 단가·포장 분할 조건이 있으면 입력을 보존하고 처리를 차단한다.

응답 유실 시 최초 요청으로 서버 결과를 조회하고 같은 원문으로 재시도하거나 명시적으로 중단한다. 새 요청은 서버에서 중단과 늦은 작업 차단을 확인한 다음 시작한다. 옛 클라이언트 작업은 서버의 원래 전체 생산 계획을 증명할 수 없는 경우 자동 재개하지 않는다. 효과가 없음을 확인하고 늦은 실행을 차단할 수 있는 경우에만 중단 후 새 생산으로 이어진다. 현재 배합으로 과거 생산량을 추정하지 않는다.

프로젝트는 회사별로 분리한다. 참여자가 열람·수정하고 해당 회사 관리자는 전체 관리한다. 전역 메뉴에는 프로젝트 하나를 추가하며 프로젝트 목록·작업·댓글·체크리스트는 본문에서 관리한다. 첫 버전은 주문·생산 기록과 독립적인 업무 관리다.

세금계산서 조회는 앱에 보관된 발행 원본을 현재 주문 목록과 별개로 조회하고 공통 날짜 필터를 제공한다. 국세청·홈택스 발행 조회 연동이 추가된 것은 아니다. 관리자 확인사항의 필터는 표 밖으로 이동했다.

ERD는 첨부 원본과 기존 카드·관계·좌표·양식을 보존하고 현재 스키마를 113개 논리 표로 대조했다. 논리 표 수는 실제 최상위 컬렉션 수나 운영 문서 수가 아니다. 기존 운영 자료의 수량·금액·과거 월말 기록을 수정하지 않았다.

검증은 단위·React·실제 로컬 Web/Admin SDK·권한 규칙·의미 변이·HTTP 인증 경로를 구분했다. 실제 두 탭의 잠금 시험은 브라우저 잠금과 공유 저장소를 검증했고 서버 응답에는 합성 포트를 사용했다. HTTP 시험은 별도로 실제 onCall 래퍼와 Auth 에뮬레이터를 통해 부분 생산 및 원료 정정의 실제 저장·중복 적용 방지를 확인했다. 반복 실행한 시험 수를 합산하지 않는다.

배포 후에는 보호 규칙 원문, 새 이름공간 사전 문서 유무, 인덱스 준비 상태, 영향받는 서버 소스와 기존 함수 상태, 양앱 공개 파일을 대조한다. 보호된 처리 기록을 삭제해 되돌리지 않으며 구형 서버로의 복귀는 새 보호 필드 및 처리 계약과의 호환성을 먼저 확인한다.
