# 프로젝트 UI·생산창 수량 조절 배포

2026-11-02 사용자 명시 승인으로 제품 `2cb4b8c51b95a520e6eaa330ebb5a61de39d3d39`를 관리자·직원 Hosting에 배포하고 공개 파일 183개의 SHA를 고정 빌드와 대조했다. 앞서 준비한 프로젝트 UI `d1816a2`를 포함한다. 앞선 자동 승인 검토에서 배포 명시 승인이 부족해 실행 전 차단된 뒤, 사용자가 두 수정의 배포·검증·main 반영을 함께 허용했다.

카드의 별도 ‘부분 생산 완료’ 버튼을 제거했다. 기존 품목 체크와 생산 처리에서 열리는 생산창 안에서 기존 재고 사용량과 이번 생산량을 입력하고, 이번 완료 합계·완료 누계를 확인한다. 주문·배송·캘린더·주문 수정의 기존 진입을 같은 제어기로 연결하며 선택한 품목만 기본 선택한다. 추가 재고 생산은 같은 창에서 선택한다. 프로젝트 목록·보드·모달도 공통 입력·버튼 규격과 배치로 정돈했다.

실제 로컬 서버 거래에서 주문10에 생산4→완료4/10, 다시6→완료10/10과 원료100→96→90을 확인했다. 재고3+생산2→완료5·원료98, 재고3+생산0→완료3·원료100, 5개입 박스2 생산과 기존 낱개2 사용→원료8만 사용도 확인했다. 같은 원문 적용은 중복 차감하지 않으며, 실제 서버 미리보기와 화면의 재고3·생산2·완료5가 일치했다. 인증·전송은 합성 포트이고 거래는 실제 로컬 Admin SDK다. HTTP 인증 시험이나 운영 자료 시험으로 보고하지 않는다. 반복 실행은 사례 수에 합산하지 않았고 자체 UUID 자료 정리와 감시 문서 보존을 확인했다.

최종 전체 시험은 1,200파일에서 12,630통과·실패0·환경 조건 생략2,016이다. 최초 실행의 변경 외 위생 화면1실패는 원문을 보존했으며, 해당 시험 파일의 단독31통과 후 제품·기대값 변경 없이 전체를 다시 검증했다. 앱 타입·양앱 빌드와 독립 코드·1440/390 실제 컴포넌트 검수가 통과했다. 합성 미리보기의 수치 한계는 실제 준비 응답·DOM 대조로 별도 보완했다. 같은 신원의 인증 재확인 시 입력을 유지하고 실제 계정·회사·직원·권한 세대 변경은 이전 선택과 응답을 차단한다.

구형 방식에서 이미 완료 기록이 생긴 주문은 기존 정상 처리·취소·복구 경로를 유지한다. 과거 기록을 새 생산 배정으로 자동 승격하거나 현재 배합으로 추정하지 않는다. 상품·OEM·재고 생산의 기존 별도 흐름도 보존한다. 확인된 무효과 중단 표식은 새 생산 후보로 연결하되, 기존 서버가 원문·영수증을 최종 검증한다. 서버 거절을 옛 경로 자동 재송신으로 우회하지 않는다.

이번 배포는 Hosting만 갱신했다. 기존 서버 71개 모두 ACTIVE·Node22이며 전부 revision과 갱신 시각이 직전 배포와 동일하다. 기존 검증 대상18개 소스 ZIP의 컴파일 JS202개도 현재 산출물과 일치한다. 규칙 SHA `29ba5ff0858bd3c47b2a1d6e98983ce33eed8c097e3a31c7a0b011f4466362b0`와 필수 인덱스14개 READY를 읽기 확인했다. Functions·Rules·인덱스·운영 주문/전표/재고 자료·IAM·키를 수정하지 않았다. FCM 원문 SHA `A5A5B637133A0EECCFFB7553FDB36510631191A0CFAA51002B79AC5FBC37F794`도 유지했다.

ERD의 113개 논리 표·기존 카드·관계·좌표·원본은 그대로이며 화면 배포 상태만 갱신했다. 운영 검증 후 같은 제품 소스와 마감 기록을 main에 반영한다. 이전 원료·생산 서버 계약은 `49e65b8`을 유지하므로 롤백 시 새 보호 표식을 지원하는 호환 소스를 사용하며 자료나 처리 영수증을 삭제하지 않는다. 상세 원문은 로컬 `work/production-flow-*`, `production-quantity-*`, `quantity-modal-qa`에 보관하며 개인·인증 자료는 커밋하지 않는다.
