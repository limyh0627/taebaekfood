# 전표 처리 상태와 구형 대체 템플릿 후속

사용자가 정상 발행 직전 실패 안내가 잠깐 나타나고 실패 목록이 남는 현상, 대체 갈래에 거래처가 있으면 매입으로 발행되는 현상을 제보했다. 개별 운영 전표 원문을 조회해 해당 사례 원인을 확정한 것은 아니다. 코드에서 재현 가능한 경로를 별도로 확인했다.

일반전표 `VoucherComposer`는 송신 전에 보관한 요청을 정상 응답 대기 중에도 “이전 전표 재시도” 영역에 표시한다. 매출·매입 `TradeStatement`는 별도 보관 체계의 모든 미삭제 요청을 실패 건수로 세고, 저장 대기 중 복구창 진입을 허용한다. 일반 저장 성공 후 작성창은 닫지만 복구창 상태가 남을 수 있다. 두 화면의 사본을 같은 요청으로 혼동하지 않는다.

정상 송신 중 요청은 처리 중으로 표시하고 재시도 안내·중복 복구 진입과 분리한다. 같은 작성 요청의 발행·후속 처리·사본 정리가 확인된 경우 복구창의 선택·조회 상태를 닫는다. 전표 발행 ACK 뒤 결제나 완료 확인만 실패하면 “전표 발행 완료, 후속 확인 필요”로 안내한다. 다른 요청의 미확정·손상 사본을 일괄 삭제하거나 숨기지 않으며 기존 회사·UID·원문 CAS 보호를 유지한다.

이전 종류 분리 수정은 현재 코드에 포함돼 있다. 직접 거래처를 바꾸는 동작은 전표 종류를 변경하지 않는다. 남은 경로는 수동으로 선택한 옛 템플릿의 `statementType`이 없고 방향이 대체인 경우다. 기존 호환 판독이 거래처 존재를 보고 매입을 추론하고 화면이 그 종류를 저장한다. 서버와 관리자 저장 콜백은 전달한 종류를 다시 바꾸지 않는다.

수동 선택의 해당 구형 대체 템플릿에만 지역 복사본의 종류를 비용(일반 대체)으로 명시하고, 종류·분개행·면세 판정이 같은 복사본을 사용하도록 맞춘다. 명시 종류가 있는 템플릿과 다른 방향은 유지한다. 운영 템플릿을 자동 수정하거나 기존 자동발행의 호환 판독을 바꾸지 않으며 계정·차대변을 임의 생성하지 않는다. 이미 보관한 최초 요청의 종류도 바꾸지 않는다.

제품·시험5파일과 문서5파일의 정확 범위를 등록해 구현을 동결했다. Trade100개·Voucher31개, 고유131개 관련 시험이 통과했다. 송신 중 필터 보호를 제거한 변이1개 실패, 일반전표 처리 중 표시와 구형 대체 종류 보호를 제거한 변이 각1개 실패를 검출하고 원문을 복원했다. 정상 지연 응답·성공 닫힘·응답 유실·발행 후 결제/정리 실패·회사/UID 전환과 실제 구형 대체 저장 종류를 회귀로 확인한다. 기존 원문 충돌 회귀는 사본이 정리되지 않아도 창을 닫던 기대를 원문·창 유지와 발행 완료 안내로 보강했다. 구현 중의 치환 누락 실패·이전 실행을 최종 통과와 합산하지 않는다.

일반전표의 응답 유실 안내도 저장 실패로 단정하지 않도록 보완했다. 송신 후 쓰기 없음 증거가 없는 경우 저장 결과 미확인과 같은 요청 재시도를 안내한다. 검증된 미저장 증거가 있는 거절, 전송 전 입력·보관 오류를 구분한다. 사본 삭제 조건과 재시도 원문은 바꾸지 않았다. 해당 보완은 기존 회귀에 단언을 추가한 것으로 고유131개에 중복 가산하지 않는다.

독립 담당이 동결5파일 SHA·계약·회귀 근거와 최종 안내문을 대조해 미해결 P1/P2가 없음을 확인했다. 실제 컴포넌트를 합성 서비스와 연결한 브라우저에서 거래처가 있는 옛 대체 양식의 일반 대체 종류·균형 분개·저장 요청 `type:비용`을 확인했다. 정상 송신 대기 중 재시도 안내 숨김, 성공 시 작성창 종료, 응답 유실 안내와 최초 요청 보존, 같은 ID·원문 재시도 후 성공 종료를 확인했다. 거래명세서 정상 송신 중 실패 건수0·복구 진입 차단·성공 후 복구창 잔존 없음, 발행 후 사본 정리 오류의 발행 완료 안내·확인 필요 목록도 확인했다. 390폭에서 복구 목록과 안내를 확인한 뒤 viewport를 원복했다. 비공개 화면 근거는 `records/statement-legacy-type-final-20261016.jpg`다.

최종 앱 타입 검사와 관리자21.19초·직원14.53초 빌드가 종료0으로 완료됐다. 필드 사전 자체 검증과 check-only도 종료0이며95컬렉션·739직접 필드·501소스·637참조 필드·3509미해석 접근·713wrapper다. 별도 거래처원장 후보2파일은 백업 검증 후 HEAD 바이트로 한시 분리한 상태에서 사전·타입·양 빌드·QA 번들을 만들었고, 완료 후 CAS 대조로 후보 원바이트를 복원했다. 해당 후보는 이번 통합·배포에서 제외한다. FCM 생성물은 기존 원바이트 SHA를 유지했다.

운영 Auth·서버 통신과 실제 업무 자료를 사용한 시험은 하지 않았다. 실기기 검수는 사용자 지시로 제외했다. 모든 가드와 모든 오래된 사본의 고착 원인을 해결했다고 확대하지 않는다. 운영 조회·쓰기·서버/Rules 변경은 하지 않았다. main·Hosting 결과는 확인 후 기록한다.
