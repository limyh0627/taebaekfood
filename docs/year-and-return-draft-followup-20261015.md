# 새해 분석 연도와 반품 작성 초안 후속

직접 재현한 두 원인을 별도 묶음으로 보완한다. 원본 TODO 전체 완료 판정과 구분하며 운영 자료를 수정하지 않는다.

## 분석 연도

같은 자료 배열로 새해에 화면이 다시 렌더링돼도 연도 선택지에 새해가 추가되지 않았다. 현재 연도를 메모 계산의 입력으로 포함한다. 사용자가 고른 과거 연도를 자동 변경하거나 손익 계산을 바꾸지 않는다. 실제 컴포넌트와 연도 선택기를 통해 연도 변경과 기존 선택 보존을 검증한다.

## 반품 초안

거래처를 먼저 고른 뒤 품목·거래처 연결 자료가 도착하면 자동 품목 행이 비어 있었다. 자동 채움이 가능한 미수정 초안과 사용자가 수정한 초안, 처리를 마친 초안을 구분한다. 수량을 비우거나 0으로 입력한 경우도 사용자 수정으로 취급한다. 자료 도착 때문에 수량·메모·금액·발생계정·원전표 선택을 덮어쓰지 않으며 처리 완료 후 자동 행을 다시 만들지 않는다. 기존 회사·로그인 계정별 초안 분리와 연결 품목 우선 정책을 유지한다.

## 범위와 검증

제품은 ProfitAnalysis와 신규 yearOptions 시험, ReceivingReturnsManager와 기존 companyDraft 시험의 네 파일이다. 이 문서까지 총 다섯 파일이며 앞선 날짜·과거 전표 조회 배포와 커밋을 분리한다. 집중 회귀·보호 제거 변이·독립 검수·실제 합성 화면·타입·최종 양 앱 빌드·배포는 완료한 결과만 이어 기록한다.

구현 후 집중 검증: 실제 ProfitAnalysis와 PeriodPicker의 연도 전환·선택 표시 회귀 및 기존 회사/선급금/재고평가 시험까지 4파일 12개를 통과했다. 현재 연도 의존성 제거와 기존 선택 옵션 제거 변이는 각각 1개 회귀가 검출했다. 반품은 companyDraft 16개와 기존 atomic 7개로 2파일 23개를 통과했다. 수량 0·빈 입력·행 추가·전부 삭제·원전표 선택/해제·금액/계정/비고 보존과 이전 접수 확인 성공 후 자동 재생성 차단을 포함한다. 자동 채움 보호 제거는 5개, 자료 의존성 제거는 2개 회귀가 검출했고 원본 바이트 복원 후 재통과했다. 두 영역의 관련 고유 시험은 총 35개다. 설계 담당 한 명의 최종 읽기 검토에서 기존 계약과 일치함을 확인했다. 독립 검수와 최종 타입·양 앱 빌드·실화면 검수는 진행 중이다.
