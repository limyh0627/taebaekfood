별도 실행CLI는 기본 inspect 읽기다. 적용·복원은 명시 회사·원본 백업·승인 hash를 확인하고 전체 원문/버전 대조 후 배타적 lock과 영구 intent를 남겨야 가능하다. 확정 거절은 이유와 새 dry 계획 확인 행동을 안내하고, 결과 미확정이나 영수증 저장 실패는 원문·intent·lock을 보존해 자동 재적용/복원을 막는다. 실제 적용·복원은 도구 검증과 사용자 명시 승인 전까지 수행하지 않는다. 이 단계의 신규 도구와 테스트는 아직 구현 중이다.

CAS로 중단된 뒤의 복구 경로도 포함한다. 기존 v1 백업을 덮지 않고 명시한 -v2 등 새 revision에 최신 dry 계획을 만들 수 있게 경로 검증을 공용화한다. 고정 work·회사·날짜 범위만 허용하고 새 계획은 새 hash로 다시 확인한다. revision 번호를 자동 선택하거나 기존 백업을 덮지 않는다. 다른 revision에 미확정 intent/lock이 있으면 새 파일명으로 실행을 우회할 수 없으며, inspect 읽기와 새 dry 준비만 허용한다. 실제 새 revision 백업은 정확 경로를 별도 등록한 뒤에만 생성한다.

REST adapter는 합성27개 시험과 좁은 타입 검사, 나노초 CAS·거절 판정·결과 나노초 보호 제거 변이3종을 통과했다. 제품 source 동결 후 실제 로컬 Firestore REST2개도 통과했다. `price` 한 필드 삭제와 원가42·수량7 보존, 실제 쓰기 시각 나노초 영수증, 조건부 복원2문서, 둘째 문서 CAS 실패 시 묶음 효과0을 확인했다. 최초 실시험2개는 fixture 인증 누락으로 seed 단계에서 거절돼 성공 근거로 세지 않았고, 시험 준비만 보완한 뒤 재실행했다. 테스트의 고정 운영 요청은 검수용 transport에서 자기 demo 프로젝트와8294 주소로만 대조·치환했다. 운영 통신은0이며 UUID 문서와 자기 에뮬레이터를 정리했다.

실행 도구 검수에서 확인된 복구 경계도 보완했다. 기본 inspect는 계속 읽기 전용이다. 사후 확인에 실패해 완료 영수증과 잠금이 함께 남으면, 명시한 `--release-verified-lock` 확인 모드에서 현재 전체 원문·버전·영수증·전송 의도·자기 잠금의 연결과 잠금 내용 불변을 확인한 뒤에만 로컬 잠금을 해제한다. 거절 표시는 허용 코드와 동일 작업·계획·모드 증거가 있어야 인정한다. 다른 모드의 미확인 의도는 inspect뿐 아니라 직접 apply/undo 진입 전과 최신 자료 조회 후에도 먼저 차단한다.

최종 관련5파일73개 시험이 통과했고, 선택 SDK4개는 별도로 표시했다. 이 중 adapter 실제 REST2개는 위 로컬 실행에서 통과했으며 나머지 기존 SDK2개는 이번 단계에서 실행하지 않았다. 최종 보완의 직접 우회 회귀와 보호 제거 변이는 검출 후 복원했고 좁은 타입 검사와 실제 Node self-check도 통과했다. 독립 최종 exact9 검수 CLEAR 및 시험 담당의 최종 SHA/self-check를 확인했다.

총괄의 기본 inspect에서 태백402건·풍회6건 모두 현재 전체 원문과 나노초 버전이 원본 백업과 일치해 ready를 반환했다(exit0, writes0). 원본 두 계획 hash는 위 정식 dry와 동일하다. 실제 apply/undo나 새 revision 백업·sidecar는 생성하지 않았으며, 운영 필드 삭제는 정확한 대상에 대한 명시 승인 후 단계다. 이 묶음은 실행 도구·시험·문서 변경만 포함하므로 앱 재빌드나 Hosting 배포 대상이 아니다.
