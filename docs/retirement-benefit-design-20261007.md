## 1차 기능 계약

직원 상세에는 회사/직원, 제도 ‘퇴직금’, 관리 기준일, 원래 입사일, 퇴직금 산정 대상 구간, 마지막 확정 정산 종료일, 장부 충당 잔액과 이벤트 이력을 표시한다. 대상 구간은 실제 확인 자료로 입력하며 중간정산으로 원래 입사일이나 연차 근속을 초기화하지 않는다.

법정 예상 퇴직금은 장부 충당 잔액 옆의 별도 항목이다. 1차에는 ‘미산정’으로 표시한다. 월급÷12를 자동 계산하거나 법정 확정액으로 표시하지 않는다. DB/DC 모델과 납입 기능은 현재 제도에 합치지 않는다.

### 제안 모델 — 아직 실제 스키마가 아님

직원 설정은 회사 ID·직원 ID·제도·관리 기준일·대상 구간·버전을 가진다. 금액은 설정 문서의 가변 총액 대신 확정 이벤트에서 집계한다. 이벤트는 다음 공통 필드를 가진다.

- 회사/직원 ID, 안정적인 이벤트 ID와 operation ID, 종류, 효력일, 기록시각, 기록자 ID, 사유, 원본 버전.
- 상태: 초안/확정/취소. 수정은 기존 확정 이력을 덮어쓰지 않고 원 이벤트를 참조하는 취소·대체 이력으로 남긴다.
- 관련 회계전표 ID와 연결 상태: 미연결/연결/연결 대기/오류. 전표의 존재·회사·금액을 확인한 경우만 연결로 표시한다.

| 이벤트 | 필수 입력 | 장부 충당 영향 |
| --- | --- | --- |
| 기초 충당 | 기준일, 입력 금액, 장부 출처, 직원별 배분 근거 | 기준일 기초에 가산 |
| 월별 적립 | 귀속 월, 적립액, 사유, 선택적 급여대장/충당전표 연결 | 가산 |
| 중간정산·최종정산 | 대상 시작/종료일, 총액, 세액, 기타 공제액, 실지급액, 충당 사용액, 지급일/연결 근거 | 확인된 충당 사용액만 차감 |
| 정정 | 원 이벤트, 정정 사유, 변경 입력값 | 원 효과 취소 후 대체 효과 적용 |

정산 총액과 충당 사용액은 동일하다고 추정하지 않는다. 총액 = 세액 + 기타 공제액 + 실지급액의 입력 대사를 검증하고 불일치하면 확정하지 않는다. 세액 자동 산출이나 개인별 과세 판단은 하지 않는다. 충당 사용액이 현재 잔액을 넘으면 차이를 표시하고 별도 확인 없이 숨기거나 잔액을 0으로 보정하지 않는다.

기초 금액이 없으면 0으로 추정하지 않고 ‘기초 미확인’으로 표시한다. 월별 적립은 수기 입력이 기본이고 자동 급여 연결은 2차다. 같은 직원/귀속 월의 정규 적립은 중복 확정을 막고, 추가 정정은 원 이벤트를 참조해야 한다.

기존 원본의 추가 항목을 보존한다. 직원별 대상 여부, 전월/당월 충당·정산·잔액을 표시하며 정산에는 직원 요청·사유·증빙 참조와 퇴직소득세/지방소득세 각각의 입력을 남긴다. 사유와 증빙은 기록 항목이며 프로그램이 법적 적격성을 판정하지 않는다. 기초 누적분을 첫 달 비용에 몰아 넣지 않고, 기초/정산을 두 번 반영하지 않는다. 월 적립의 미리보기와 별도 연결전표 선택은 2차에 둔다.

이후 산정에서 제외하는 구간은 확정 정산이 완료된 대상기간뿐이다. 초안·취소 정산은 근속 구간을 소진하지 않는다. 연결전표가 있는 수정·삭제·취소는 재승인과 정리 순서를 구현 계약에서 명시한 뒤 수행하며 원전표와 이력의 상태가 달라지면 전체 성공으로 표시하지 않는다.

## 장부 대사와 저장 경계

기준일별 직원 장부 충당 = 확정 기초 + 확정 적립 − 확정 충당 사용액 + 유효 정정 효과다. 취소 이벤트를 이중 합산하지 않는다. 회사별 직원 합계를 같은 기준일·계정 범위의 회계 충당 잔액과 비교하고 **회계 잔액 − 직원 합계**를 미배분 차이로 별도 표시한다. 차이를 직원에게 자동 분배하거나 비용·현금 전표로 만들지 않는다. 회계 자료가 없으면 ‘대사 불가’로 표시한다.

1차 수기 이력 저장 자체는 금융전표를 만들지 않는다. 실제 지급이나 회계 충당 전표와 연결하려면 기존 회사별 공용 명령·번호·권한 계약을 별도로 검토해야 한다. 급여 실수령과 퇴직금 적립·정산을 분리하며 같은 지급을 급여와 정산에 중복 기록하지 않는다.

원본의 후보 계정은 적립 차변806/대변295, 지급 차변295(부족분806)/대변통장·257이다. 이는 기존 설계 후보이며 현재 회사 계정표와 실제 장부를 대조하기 전 확정 규칙으로 사용하지 않는다. 충당만으로 통장 잔액이 변하지 않고 비용이 손익에 한 번만 반영돼야 한다. 기존 수동 충당전표와의 중복을 안내하며 `AdminApp.tsx`의 `onCreatePayrollAccrual` 연결은 구현 단계에서 조사한다.

직원 설정·이벤트 확정은 회사/직원 일치, 마감 기간, 원본 버전, operation 중복을 서버에서 검사한다. 병렬 확정은 같은 원본 버전에서 하나만 성공해야 한다. 회계 연결을 동일 transaction에 포함할 수 없는 경로는 연결 대기 상태와 멱등 재시도를 사용하고 전체 성공처럼 표시하지 않는다. 취소·수정도 마감과 연결전표 상태를 다시 검사한다. 회사 전환 후 옛 확인창과 늦은 응답이 새 회사에 쓰거나 표시되지 않도록 한다.

## 구현 전 필요한 실제 자료

회사별 기초 기준일과 회계 충당 계정/잔액, 직원별 배분표와 미배분 차이, 확인된 산정 대상 구간·기존 정산 종료일, 월 적립 정책/근거, 과거 정산의 총액·세액·기타 공제·실지급·충당 사용액 및 관련 전표가 필요하다. 자료는 권한 있는 로컬 경로에서만 확인한다. 직원 개인정보를 노션에 게시하지 않는다. 현재 자료가 없으므로 실제 금액과 계정 코드를 채우지 않았다.

## 단계와 인수 조건

1. 기초/수기 이벤트·직원 상세·회사 대사: 실제 자료와 구현 승인 후 진행한다.
2. 월별 급여 연결·충당전표 선택: 중복과 부분 실패 처리 계약을 확인한 뒤 별도 구현한다.
3. 법정 예상액·세액: 계산 기준과 검증 자료를 별도로 확인한 뒤 검토한다.

구현 인수 시험에는 자기회사 성공·타회사 및 직원 위조 거절, 중복 재시도, 동시 확정, 저장/회계 연결 부분 실패와 재시도, 수정·취소, 마감 기간 거절, 원 입사일/연차 보존, 정산 입력 대사, 직원 합계와 회계 잔액 차이 표시를 포함한다. 현재 문서는 이 계약의 구조 검토를 완료한 것이며 실행 시험이나 전체 기능 완료를 주장하지 않는다.

원본 요구와의 대조: 직원 상세·기초 충당·월 적립·중간정산 기간/금액 구분·이벤트 이력·장부 대사·단계안·회사/중복/동시/취소/마감 경계를 모두 명시했다. 남은 사항은 실제 자료 확인과 구현·운영 적용 승인이다. 노션 상태 변경과 운영 쓰기는 없다.
