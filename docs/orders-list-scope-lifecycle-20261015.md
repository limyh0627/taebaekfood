# 주문 목록의 강조 표시와 회사별 조회 수명

주문 목록에서 이전 주문의 타이머나 다른 회사·사용자의 비동기 결과가 현재 화면에 남지 않도록 세 경계를 보완한다. 기존 주문·원장·회사 설정의 업무 값이나 서버 저장 방식은 바꾸지 않는다.

## 강조 표시 타이머

기존 강조 effect는 첫 타이머의 콜백 안에서 다음 타이머의 정리 함수를 반환했다. React는 이 반환값을 effect 정리로 사용하지 않으므로 주문 전환이나 화면 종료 뒤 이전 강조 해제 콜백이 실행될 수 있다. 바깥 effect가 두 타이머를 소유하고 모두 정리한다. 콜백의 최신 참조를 사용하되 부모의 인라인 함수가 바뀌었다는 이유만으로 강조 시간을 다시 시작하지 않는다.

## 회사별 작업 그룹

기존 구독은 그룹 이름이 있는 문서를 받았을 때만 화면 상태를 바꿨다. 회사가 바뀌고 새 회사의 문서가 없거나 빈 배열이면 이전 회사의 그룹이 남았다. 회사 구독을 시작할 때 기본 그룹으로 초기화하고 없는 문서·빈 배열도 기본값으로 처리한다. 이전 구독의 늦은 콜백은 무시한다. 기존 회사 설정 함수와 저장 경로를 재사용하며 조회 과정에서 기본값을 서버에 쓰지 않는다.

## 주문 로그 조회

기존 로그 effect는 선택한 주문 ID만 의존하고 회사·실제 로그인 사용자의 전환을 처리하지 않았다. 회사 A에서 B로 갔다가 A로 돌아오거나 사용자가 바뀌었을 때 이전 로그 선택과 늦은 결과가 남을 수 있다. 회사·사용자가 바뀌면 선택과 결과를 닫고, 조회를 시작한 회사·사용자·주문·화면 세대가 같은 경우에만 결과를 반영한다.

다른 회사에 같은 주문이 없으면 기존 모달 자체가 숨겨지므로 회사 전환 즉시 이전 로그가 노출된다고 확대하지 않는다. 기존 `fetchWhere`와 `buildOrderActivityLog`는 재사용하며 서비스 전체의 조회 계약을 이 변경에서 새로 정의하지 않는다.

## 검증 범위

강조 타이머 시작 전후의 화면 종료, 주문 강조 전환, 정상 스크롤·해제, 회사 그룹의 없음·빈 배열·정상 문서와 늦은 콜백, 회사 A→B→A 및 사용자 전환의 로그 종료·늦은 응답을 실제 컴포넌트로 검증한다. 보호를 제거한 변이가 실패하는 것을 확인하고 원복한다.

정확한 두 제품 파일의 구현과 독립 검수를 마쳤다. 신규 실제 컴포넌트 9개와 기존 관련 6파일 31개를 합친 고유 7파일 40개 시험이 통과했다. 타이머 정리·그룹 범위·회사 전환 초기화 보호를 각각 제거한 변이는 실제 회귀 실패를 검출했으며 원래 바이트로 복원했다. 새 산식·서버·운영 자료 쓰기는 추가하지 않았다.

실제 화면과 최종 타입·빌드·배포는 완료한 단계만 추가 기록한다. 전표 삭제·재작성 배포의 고정 산출물을 별도 보존해 두 후보가 섞이지 않게 한다. 원본 TODO 43개 중 완료 22개·잔여 21개 집계를 이 부분 보완만으로 변경하지 않는다.

최종 앱 타입 검사와 관리자·직원 빌드가 모두 통과했다. 실제 OrdersList를 사용한 운영 연결 없는 합성 화면에서 회사 그룹 초기화와 종료된 구독 응답 무시, 로그인·회사 전환의 로그 닫힘과 현재 사용자 응답만 반영, 연속 강조의 마지막 주문 1회 해제, 화면 종료 뒤 추가 해제 콜백 0회를 확인했다. 화면 검수 증거는 저장소 밖 records에 보관한다. 아직 이 묶음의 main 반영·Hosting 배포 완료를 뜻하지 않는다.
