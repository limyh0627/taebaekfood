# 월말 재고 상세와 현금출납장 후속

기준 main은 `403bc16`이다. 이번 후속은 수정·시험 범위이며 배포와 과거 운영 자료 수정은 포함하지 않는다.

## 월말 품목별 내역

자동 월말 기록이 기존 평가 함수의 회사별 합계만 저장하고 품목별 평가 줄을 버리고 있었다. 같은 조회에서 읽은 품목명·규격과 이미 계산된 수량·평가액을 기존 `items` 필드에 함께 저장하도록 수정했다. 금액 계산·회사 구분·문서 ID·기존 문서 건너뛰기·권한 전환 확인·실행 시각은 유지한다. 기존 월 문서에 상세가 없어도 덮어쓰지 않는다.

화면에서는 모든 월을 버튼으로 펼칠 수 있다. 품목 내역 미기록·빈 배열은 당시 원본 확인이 필요하다고 안내하고, 손상된 목록은 확인 불가로 구분한다. 빈 배열을 실제 재고 0으로 단정하거나 현재 재고로 과거 내역을 채우지 않는다. 기존 일부 월의 상세는 여전히 없어, 당시 원본·백업에 근거한 별도 복원이 필요하다.

실제 스케줄러 callback 전체를 추출한 모의 거래 시험으로 저장 내역·총액 동치·기존 월 보존·실패 시 저장하지 않는 동작을 확인했다. 실제 운영 스케줄러 실행이나 Firestore SDK 시험으로 확대하지 않는다. 설정상 실행 시각과 기존 주석의 불일치는 별도 확인 사항이며, 이번 승인에 따라 설정을 변경하지 않았다.

## 현금출납장

열 너비를 고정하고 긴 적요·거래처·계정 문구를 줄바꿈해 다른 열을 화면 밖으로 밀어내지 않도록 수정했다. 좁은 화면은 표 내부에서 가로로 스크롤하며 금액을 생략하지 않는다.

기존 `전표 n건`은 연결 기록 개수를 세고 있었다. 같은 전표가 중복 연결된 경우를 제외한 고유 전표 수를 `연결 전표 n건`으로 표시하고 기존 매칭 창을 열도록 연결했다. 창 열기만으로 자료를 저장하지 않으며, 잔액 조정·확정 잔액의 연결 표시는 읽기 전용으로 유지한다. 잔액·매칭 금액·삭제·정산 데이터는 변경하지 않는다.

## 최종 검증

관련 일반 시험은 실제 실행된 10파일 74건 통과·실패0·생략0이다. 결과는 `work/monthly-cash-final-20261101.json`이다. 입력 필터 목록의 존재하지 않는 별도 평가시험 경로는 실행 수에 포함하지 않는다. 실제 handler 시험은 기존 평가 함수를 그대로 호출한다.
