# 원장 수량 표시와 매입 작성 거래처 선택 후속

긴급 전표 수정의 main 반영·양 Hosting 공개152파일 대조를 마친 뒤, 사용자 지시대로 가능한 TODO를 이어간다. 보존한 원장 소수 표시 후보와 코드에서 재현한 거래처 오선택 두 건을 함께 처리한다. 원본43개 중26완료·17잔여는 유지하며 과거 자료가 필요한 여섯 범위와 기존 보류를 재개하지 않는다.

거래처원장 전표 상세 수량이 금액 표시 함수의 반올림을 적용받던 것을 기존 공용 `formatQuantity`로 표시한다. 금액·합산·단가·원장 계산·저장 값은 바꾸지 않는다. 결측·NaN의 기존0 처리와 Infinity의 기존 확인 안내를 유지한다. 앞 묶음에서 구현·18개 시험·표시 보호 변이·독립 검수를 마친 정확2파일 후보를 원바이트 보존했으며 이번 통합에서 최종 검증한다.

관리자 확인사항의 선입고·발주예정 매입전표 작성 진입은 명시 거래처ID와 이름 조건을 같은 `find`에서 검사한다. 거래처 목록 앞의 A가 B와 이름이 같거나 일부가 일치하면 발주에 명시한 B가 존재해도 A로 작성 콜백을 보낸다. 실제 함수를 AST 추출해 메모리에서 실행한 재현에서 거래처A·B단가123·원수량2.5·원발주ID가 섞인 결과를 확인했다. 관리자 앱은 그 거래처ID를 그대로 작성 화면에 전달한다. 운영 전표를 조회하거나 발행한 재현은 아니다.

정확 거래처ID 조회를 먼저 하고, 찾지 못할 때 기존 이름 호환을 유지하도록 한정한다. 새로운 가드·자동 거래처 이관·과거 전표 수정·발주 그룹 추정 변경은 포함하지 않는다. 실제 선입고와 발주예정 버튼 클릭, 같은 이름·부분 이름·목록 순서·단일 정상·없는ID/빈ID 호환, 콜백의 발주ID·수량·단가 보존을 검증한다. 정확 ID 우선 보호를 제거한 변이가 회귀에서 검출되는지 확인하고 원바이트로 복원한다.

제품·시험4파일과 문서5파일을 등록했다. 설계는 Astra low 한 명이며 구현·독립 검수·시험/배포를 분리한다. 최종 타입·양 앱 빌드·사전과 실제 합성 컴포넌트 화면 검수를 마친 뒤 통합한다. 실기기 검수는 사용자 지시로 제외한다.

동결한 관련 시험은 Partner18개·Admin16개, 고유34개가 통과했다. Admin 신규12개는 두 실제 발행 버튼의 같은 이름·부분 이름·순서 반전·단일 정상·없는ID/빈ID 호환을 확인한다. ID 우선 조회를 제거한 변이에서 두 경로의 동일명·부분명4개 실패를 검출하고 원바이트로 복원했다. Partner 수량 표시 보호 변이의 소수2개 실패 근거도 보존한다. 독립 담당이 정확4파일의 최종 SHA·계약·시험을 대조해 미해결 P1/P2가 없음을 확인했다. 기존 실행을 중복 합산하거나 운영자료로 시험하지 않았다.

첫 타입 검사에서 신규 시험 자료의 발주 필수 필드 누락을 발견했다. 시험 담당 구현자가 실제 `PurchaseOrder`의 필수 itemId·itemName·quantity를 채우고 잘못된 poType·강제 캐스팅을 제거한 뒤 신규12개 회귀를 통과했다. 제품 소스는 불변이며 독립 담당도 최종 시험 SHA와 단언 보존을 재확인했다. 중간 실패를 최종 통과로 섞거나 시험 수에 중복 가산하지 않는다.
