# 캔 개봉 중량 단위 표시

## 확인한 원인

개봉 계획은 BOM의 kg 수량을 읽어 원료 재고에 kg로 반영한다. 그러나 표시 단위를 원료 품목의 `unit`에서 가져와 품목 표시 단위가 L인 경우 16.5kg를 16.5L로 보여 줬다. 이 표시 문제와 운영 BOM 수량의 정확성은 별개다.

## 수정 범위

새 계획의 단위를 kg로 고정하고, 과거 보존 계획의 단위가 L이어도 요약에서는 저장 중량에 kg를 붙인다. 원래 계획 객체와 최초 요청 해시를 변경하지 않으며 수량·밀도·BOM·재고·로트는 수정하지 않는다. 확인된 생들기름 캔의 BOM 16.632kg와 규격 16.5kg 차이는 별도 확인 대상으로 보존한다.

## 검증 상태

공용 계획·요약뿐 아니라 재고 화면의 보존된 최초 개봉 요청 안내도 공용 요약을 사용한다. 개당 중량 역시 kg로 표시한다. 관련 2파일 41건이 통과했고 옛 공용 표시 변이 4건·재고 안내 변이 2건이 실패해 검출됐다. 원복 후 41건과 최종 타입·diff 검사가 통과했다. 최종 관리자·직원 빌드도 통과했다.

과거 L 요청의 localStorage 원문, 확인·서비스에 전달되는 계획 객체와 공용 직렬화·SHA 해시가 그대로 유지되는 것을 시험했다.

## 합성 자료로 확인한 실제 컴포넌트 화면

운영 연결이 차단된 ItemList와 실제 개봉 모달을 별도 합성 자료로 빌드하고 IAB에서 직접 확인했다. 최초 미리보기는 Firebase 초기화 mock 누락으로 렌더링하지 못했다. CSP 연결 차단을 유지하고 초기화 모듈이 들어오면 빌드를 실패시키는 검사를 추가한 뒤, 빠진 저장 함수는 쓰기를 거절하는 mock으로 보완했다. 제품 코드는 추가 변경하지 않았다.

원료의 표시 단위 L·밀도 0.916인 합성 자료에서 과거 L 요청 2캔 카드의 `+33kg (개당 16.5kg)`, 신규 개봉 모달의 1캔 `+16.5kg`와 2캔 `+33kg`를 실제 화면에서 확인하고 캡처했다. 개봉 확정·운영 데이터 저장은 수행하지 않았다. 사용자 화면 확인 후 배포 지시에 따라 캡처 제시와 최종 확인을 기다린다.
