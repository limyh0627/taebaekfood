## 최신 사용자 정정: 숫자 입력과 단위 선택

사용자가 거래 수량·단위당 중량·입고량·금액 계산 안내를 불필요한 표시로 지적해 모두 삭제했다. 원료 매입 설정 제목과 옛 원가 근거 안내도 표시하지 않는다. 입력은 매입단위 숫자와 단위 드롭다운 두 칸으로 단순화하며 기본값은 `1 | kg`, 선택지는 kg/g다. 읽기 전용은 저장된 매입단위 값만 표시한다. 이전 자유 텍스트 화면은 사용자 승인을 받은 화면이 아니다.

숫자 20에서 g를 선택하면 20g이고 kg를 선택하면 20kg다. 단위 선택을 바꾸며 숫자를 임의로 늘리거나 줄이지 않는다. 저장된 5필드 스냅샷, kg 원가·거래처 기본단가·입고·반품은 기존 공용 계약을 유지한다. g는 공용 판독에서 1,000으로 나누고 `20g` 원문은 그대로 보존한다. 기존 포대 등 등록단위는 읽기만으로 전환하지 않는다.

현재 숫자/단위 입력·안내 삭제 화면을 실제 컴포넌트 합성 빌드로 확인했다. 서버 kg/g 공용·발행·수정 관련 104건과 변이 7건 실패 검출·원복을 확인했으며 UI·실제 직원 g 입고 후속은 최종 검증 중이다. 사용자 화면 확인·배포는 아직 하지 않았다. 아래 절은 이전 변경의 이력이다.

최종 숫자/드롭다운 검증: UI·행·가격·실제 전표 관련 5파일 156건, 실제 일반 직원 입고 SDK 6건이 통과했다. 20g×2→0.04kg와 최초 `20g` 원문, 품목·원료 상태·로트·원장 일치, 중복 쓰기 없음, 자기 문서·계정 정리 후 부재를 확인했다. 단위 변경 시 숫자를 1,000배 바꾸는 변이 4건, 숫자 문자 필터 누락 1건, 빈 숫자를 기본 1로 승격하는 변이 1건 실패를 검출해 원복했다. 최종 앱·서버 타입 및 diff 검사는 통과했고 독립 검수에서 신규 P1/P2는 없었다.

동결본으로 합성 화면을 다시 빌드하고 기본 1/kg, 20/g↔20/kg 숫자 유지, 안내 부재, 읽기 전용 단위값만 표시, 기존 입고 완료의 두 컨트롤 잠금을 직접 확인·캡처했다. 최종 캡처는 상위 records의 `manual-purchase-number-unit-final-20261013.jpg`이며 운영 연결·자료 변경은 없다. 사용자 화면 확인과 최종 전체 통합검증·양 앱 빌드·커밋·배포·푸시는 아직 별도다.

## 2026-10-13 사용자 확정 후속: kg 직접 입력

신규 원료 매입단위는 `kg`로 시작하고 사용자가 `20kg`처럼 직접 바꾼다. 등록단위 선택과 별도의 `원료 벌크 원가 기준 kg` 입력은 제거한다. 수량 2, 단위 20kg이면 전표·발주의 확정 입고량은 40kg이다. 면세 단가 44,000원은 공급가액 88,000원÷40kg=2,200원/kg으로 원가를 갱신한다. 과세 포함 단가는 기존 공용 세금 규칙으로 공급가액을 계산한 뒤 kg로 나눈다.

기존 다섯 필드 매입단위 스냅샷을 재사용하고 직접 입력만 `manual-kg`로 식별한다. 공용 단위 파서가 단위당 kg·거래 수량·입고 kg를 검증하며 발행·수정 서버도 같은 판독을 사용한다. 새 기본 kg도 스냅샷에 담아 품목의 옛 단위로 다시 환산하지 않는다. 기존 등록단위와 수동 원가 kg는 과거 원문으로 보존하며 사용자가 단위를 명시적으로 수정하기 전에는 새 기본값을 적용하지 않는다. 입고·반품 연결 잠금은 유지한다.

현재 설계·수정 범위 등록과 배정까지 완료했으며 서버·UI 구현 중이다. 아래 검증 이력은 이전 배치 변경의 근거이며 이번 kg 직접 입력의 검증 완료를 뜻하지 않는다. 최종 집중·SDK·독립 검수·화면 확인 후 결과를 갱신한다. 운영 자료 변경·배포는 아직 하지 않았다.

후속 검증에서 서버 공용·발행·수정 3파일 97건, UI·행 모델 4파일 85건이 통과했다. 별도 실제 일반 직원 Auth 입고 SDK는 20kg×2→40kg, 기본 kg, 기존 등록단위, legacy, 타회사 거절 5건을 검증했다. 서버 발행 TX의 원가 검증과 실제 직원 PO 입고는 각각 독립된 단계이며 하나의 Callable 전체 전송 시험으로 표시하지 않는다. 해당 단위·입고·원가·출력·반품 관련 집중 9파일 150건과 앱·서버 타입 검사도 통과했다. 핵심 단위 검증·rawHolder 검증·입력 변환·옛 원가 kg 제거 및 독립 입고 기대량 변이는 실패를 검출하고 원복했다.

최종 실제 입력 컴포넌트 합성 빌드를 다시 만들어 기본 kg, 20kg 입력의 40kg/2,200원 표시, 읽기 전용 동일값, 기존 포대의 입고 완료 잠금 화면을 캡처했다. 운영 연결은 CSP와 Firebase 초기화 모듈 차단으로 금지했다. 캡처는 private `records` 상위에 있으며 제품 Git에 포함하지 않는다.

## 원인과 수정 범위
