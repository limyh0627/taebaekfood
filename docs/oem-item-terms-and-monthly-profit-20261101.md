# OEM 품목별 조건과 월별 손익 상세 · 2026-11-01

## 바뀐 흐름

외주 발주 모달의 **OEM 조건 관리**에서 등록된 외주공장과 입고 품목을 선택하고, 각 품목의 가공비·업체 부자재비를 저장한다. 단가 기준은 kg·개·박스이며 부가세 포함 단가와 과세 구분을 명시한다. 개입수나 박스 근거를 확인할 수 없는 단위는 입고 시 거절한다.

발주는 보낼 원료를 기준으로 진행한다. 입고 품목은 발주 원료로 제한하지 않는다. 입고할 때 여러 규격과 실제 수량을 선택하면 각 품목의 조건을 불러온다. 선택한 조건은 사용자가 확인한 뒤 입고 원문에 고정된다. 조건을 나중에 수정해도 기존 입고·전표·재시도 원문은 바뀌지 않는다. 기존 V1 요청의 단일 kg 요율과 복구 형식도 유지한다.

가공비와 업체 부자재비는 매입전표의 별도 줄로 표시한다. 업체 부자재 비용으로 우리 창고의 자재 재고를 늘리지 않는다. 기존 부자재 원가와 별도 업체 청구가 함께 있으면 별도 비용인지 명시 확인해야 한다. 일반 로트 원가 체계와 기존 OEM 배치의 kg 비례 원가 배분은 변경하지 않는다.

조건은 사용 편의를 위한 기본값이다. 입고 서버는 회사·거래처·품목·단위·수량을 독립 검증하고, 서버 전용 처리 기록의 원문과 전표를 대조한다. 설정값을 서버가 보증한 가격표로 취급하지 않는다. 기존 거래처 편집의 충돌 검사와 결과 확인·재시도·중단 흐름을 재사용한다.

## 월별 손익 상세

월을 펼치면 전표 전체 목록 대신 해당 월의 매출·매출원가·판관비·영업외손익·순이익과 계정별 구성을 보여준다. 기존 분개 및 공용 손익 계산을 사용하고 월별 요약과 상세를 대조한다. 부가세·자산부채·수금지불을 별도로 더하지 않고, 이미 반영된 기초·기말 재고를 다시 조정하지 않는다. 미분류 계정도 기존 집계 기준에 맞춰 표시한다.

모바일 월별 요약 표의 가로 스크롤은 유지하지만, 펼친 분석은 화면 폭 안에서 계정명과 금액을 함께 보여준다. 전표 목록만을 위해 쓰던 조회 함수와 가져오기는 제거했다.

## 검증과 한계

실제 격리 Firestore 시험에서 OEM 입고 10건·전표 23건·조건 저장 16건을 통과했다. 원문 변경·조건 누락·중복 입고·회사 혼동·부자재 중복 및 전표 응답 유실을 확인했고, 시험 소유 문서 정리와 감시 문서 보존도 확인했다. 순수 계산·화면·복구 시험과 의미 변이를 별도로 수행했다. 이 수치는 전체 시험과 중복 합산하지 않는다.

실제 입고 컴포넌트의 PC 1440px·모바일 390px에서 10kg 10박스와 20kg 20박스의 500kg 입고, 품목별 비용 합계, 명시 확인 후 송신을 검수했다. 조건 모달의 시각 검수는 저장 훅 대역을 사용했고 실제 영속 저장은 별도 SDK 시험으로 확인했다. 손익 화면에서는 키보드 펼침·계정별 금액·순이익 및 모바일 금액 가시폭을 확인했다.

독립 코드 검수는 OEM과 손익 상세 모두 통과했다. 전체 1,170파일에서 12,301건 통과·실패 0건·환경 조건에 따른 1,896건 생략을 확인했다. 시험 선택 제외는 추가하지 않았다. 앞선 실행에서 드러난 새 입고 계약과 기존 시험의 불일치, 과거 서버 확정 조회·월말 저장 변경의 시험 반영 누락, 비동기 완료 전 검사를 정리했다. 비동기 시험은 단순 대기시간 연장 대신 영속 보관 완료·실제 편집 가능·명령 결과를 기다리며 기존 업무 검증을 유지한다.

최종 앱 타입 검사와 서버 컴파일·런타임·관리자 및 직원 앱 빌드를 통과했고 FCM 파일 해시는 유지됐다. 전체 시험 이후 시험 대역의 타입 표기만 좁힌 한 파일은 변환 JavaScript 9,247바이트의 SHA가 전후 동일함을 확인하고 집중 시험과 전체 타입을 재확인했다. 제품 실행 코드와 시험 assertion 변경은 없다.

공용 인증 리스너의 동일 틱 ABA를 실제 기기에서 검증했다고 주장하지 않는다. 운영 자료 수정·새 RPC·Rules·IAM 변경·배포는 하지 않았다. 뒤이어 요청한 부분 생산·추가 재고 생산·주문 분할은 별도 승인·설계 범위이며 이 변경의 구현 완료로 포함하지 않는다.
